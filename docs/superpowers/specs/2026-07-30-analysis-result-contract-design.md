# AI分析結果契約 設計仕様

## 目的

最新のAI分析入力JSONを読み込み、入力1市場につき1件の分析結果契約を、決定的なJSONとして出力する。

初期版の `analyze_market.py` はAI分析機ではなく、分析結果契約の固定機とする。全市場を `pending` 状態へ変換するだけとし、AI、Web検索、ニュース検索、確率予測、売買、認証、外部通信は行わない。

## 責務と変更範囲

実装段階では、次のファイルだけを追加または更新する。

- 新規: `analyze_market.py`
- 新規: `tests/test_analyze_market.py`
- 更新: `.gitignore`
- 更新: `README.md`
- 更新: `plan.md`

既存の `fetch_markets.py`、`select_candidates.py`、`prepare_analysis_input.py`、既存テスト、各段階の生成データ、`requirements.txt` は変更しない。依存ライブラリは追加せず、Python標準ライブラリだけを使用する。

本設計段階では、この設計書だけを追加する。実装コード、README、`plan.md` は変更しない。

## データフロー

```text
data/analysis_input_YYYY-MM-DD_HHMM.json
    ↓ analyze_market.py
data/analysis_result_YYYY-MM-DD_HHMM.json
```

入力JSONの内容を検証した後、入力配列の各要素から結果オブジェクトを1件ずつ生成する。並び替え、絞り込み、重複排除、AI分析は行わない。

## 入力ファイル

### 選択規則

`data/analysis_input_*.json` に一致する通常ファイルを、ファイル名の文字列昇順で並べた最後の1件を入力とする。更新日時、作成日時、実行日時は使わない。

選択されたファイル名は、次の形式へ完全一致しなければならない。

```text
analysis_input_YYYY-MM-DD_HHMM.json
```

日付と時刻は実在する暦日および24時間表記として検証する。ファイル名昇順で最後に選ばれたファイルが形式不正の場合、別の古いファイルへフォールバックせず入力不正とする。

入力ファイルはUTF-8、BOMなしで厳密に読み込む。不正なUTF-8、UTF-8 BOM、空ファイル、JSONとして不正な内容は入力不正とする。

### トップレベル

トップレベルはJSON arrayでなければならない。オブジェクト、文字列、数値、真偽値、`null` は入力不正とする。

空配列は有効入力である。要素数の上限はこの段階では設けず、上流の候補件数に関する方針を重複実装しない。

### 必須12キーと型

配列の各要素はJSON objectとし、次の12キーを必須とする。キー順は問わない。

| 順序 | 入力キー | JSON型 | 検証 |
| ---: | --- | --- | --- |
| 1 | `市場ID` | string | 空文字列および空白だけを拒否 |
| 2 | `市場` | string | 型を検証し、値は変更しない |
| 3 | `YES価格` | number | 真偽値を拒否し、有限数であることを検証 |
| 4 | `NO価格` | number | 真偽値を拒否し、有限数であることを検証 |
| 5 | `出来高` | number | 真偽値を拒否し、有限数であることを検証 |
| 6 | `流動性` | number | 真偽値を拒否し、有限数であることを検証 |
| 7 | `締切日` | string | 型を検証し、値は変更しない |
| 8 | `カテゴリ` | string | 型を検証し、値は変更しない |
| 9 | `締切までの日数` | number | 真偽値を拒否し、有限数であることを検証 |
| 10 | `URL` | string | 型を検証し、値は変更しない |
| 11 | `分析基準日時` | string | タイムゾーン付きISO 8601として検証 |
| 12 | `選定理由` | string | 型を検証し、値は変更しない |

JSON numberは、整数と小数をともに `Decimal` へ解析して検証する。Pythonの `bool` を数値として扱わない。Python標準のJSONデコーダが既定では受理する `NaN`、`Infinity`、`-Infinity` は、`parse_constant` で明示的に拒否する。

数値の値域や、YES価格とNO価格の関係、締切までの日数の候補条件は、この処理では再判定しない。それらは上流工程の責務であり、ここではJSON型と有限性だけを検証する。

全要素の `分析基準日時` は、空白やタイムゾーン表記を含む入力文字列として完全一致しなければならない。時刻として同じ瞬間でも文字列表現が異なれば入力不正とする。

`市場ID` は同一入力ファイル内で一意でなければならない。同じ市場IDが複数回現れた場合は、入力1市場につき出力1市場という対応が曖昧になるため入力不正とする。

### 重複JSONキー

入力オブジェクト内で同じJSONキーが複数回出現した場合は、後勝ちで解釈せず入力不正とする。必須キーと未知キーのどちらも同じ規則で扱う。

### 未知キー

必須12キー以外の未知キーは将来互換のため許容し、値の型を問わず結果生成では無視する。未知キーを出力へコピーしない。

入力要素に `schema_version` が存在しても未知キーとして許容する。ただし、その値は型に関係なく読み替え、検証、継承、出力バージョン決定に使用しない。

入力の `schema_version` と出力の `schema_version` は別契約である。入力値によって出力契約のバージョンを上書きすることは禁止する。

## 出力ファイル

### ファイル名導出

選択済み入力ファイル名の接頭辞と拡張子だけを置き換え、同じ `data` ディレクトリへ出力する。

```text
入力: data/analysis_input_2026-07-30_2204.json
出力: data/analysis_result_2026-07-30_2204.json
```

出力名は入力ファイル名からだけ導出する。入力要素の `分析基準日時` や実行日時とは照合しない。これにより、入力0件でも出力パスを決定できる。

同じ入力ファイルへの再実行では、同じ出力パスを原子的に置き換える。

### トップレベルと1対1対応

トップレベルは常にJSON arrayとする。ラッパーオブジェクトやトップレベルメタデータは追加しない。

入力配列の順序をそのまま維持し、入力の各要素から出力要素を必ず1件生成する。したがって、正常時は次を満たす。

```text
len(output) == len(input)
output[i].market_id == input[i]["市場ID"]
output[i].analysis_reference_time == input[i]["分析基準日時"]
```

入力要素の並び替え、除外、追加、集約は行わない。

## 出力オブジェクト契約

### 固定キー順

初期版の出力要素は、`analyze_market.py` の単一定数 `RESULT_KEYS` で次の4キーをこの順序に一元管理する。

| 順序 | 出力キー | JSON型 | 初期版の値 |
| ---: | --- | --- | --- |
| 1 | `schema_version` | string | コード定数 `SCHEMA_VERSION` の値 |
| 2 | `market_id` | string | 入力の `市場ID` をそのまま使用 |
| 3 | `analysis_reference_time` | string | 入力の `分析基準日時` をそのまま使用 |
| 4 | `status` | string | 常に `pending` |

入力の市場名、価格、出来高、流動性、締切日、カテゴリ、締切までの日数、URL、選定理由は出力へ複製しない。市場との対応には `market_id`、スナップショットとの対応には `analysis_reference_time` を使用し、詳細は不変の入力JSONを参照する。

初期版の1要素は次の形になる。

```json
{
  "schema_version": "1.0",
  "market_id": "12345",
  "analysis_reference_time": "2026-07-30T22:04:49.568055+09:00",
  "status": "pending"
}
```

## 状態設計

状態名は次の3種類を予約する。

| 状態 | 意味 |
| --- | --- |
| `pending` | 分析がまだ一度も試行されていない |
| `completed` | 将来のAI分析が成功し、契約で定義された結果と根拠が揃っている |
| `error` | 将来の市場単位の分析が試行されたが、契約で定義されたエラー情報とともに失敗した |

初期版の `SCHEMA_VERSION = "1.0"` では、生成可能な状態を `pending` だけに限定する。`completed` と `error` は意味を予約するが、初期版は生成しない。

`completed` に必要な確率、判断、自信度、根拠、反対材料、情報源、モデル情報などのキー、および `error` に必要なエラーコードや説明のキーは本設計で推測して追加しない。実際のAI分析工程を設計する際に、型、値域、必須条件、決定性、情報源の扱いを別途固定し、`SCHEMA_VERSION` を更新する。

入力不正やファイル保存失敗は市場単位の `error` ではなく、ファイル全体の処理失敗とする。初期版では結果ファイルを新規作成または置換せず、終了コード1で終了する。

## バージョン管理

### 正本

出力契約バージョンは、コードの単一定数として次の値に固定する。

```python
SCHEMA_VERSION = "1.0"
```

契約の意味、キー、型、順序、状態遷移、互換性方針の正本は本設計書とする。実装時には `SCHEMA_VERSION` と `RESULT_KEYS` をコード上の正本とし、設計書と一致することをテストする。

### 全要素の同一バージョン

1回の実行で生成する全要素の `schema_version` は、必ず同じコード定数 `SCHEMA_VERSION` から設定する。入力値、入力内の未知キー、要素ごとの状態、実行環境で変更しない。

同一ファイル内に異なる `schema_version` を混在させることは禁止する。テストでは、複数市場の全出力要素がコード定数と完全一致することを確認する。

### 0件時の例外

入力が空配列の場合、出力は正確に次の3バイトとする。

```text
[]\n
```

16進表記:

```text
5B 5D 0A
```

トップレベル配列を維持するため、空配列には `schema_version` を格納できない。この制約を実装時にREADMEへ明記する。空配列の契約バージョンはファイル内容から判定せず、生成に使用したコード、設計書、実行記録によって管理する。

### 将来の更新と移行

バージョン文字列は `MAJOR.MINOR` 形式とする。

- 後方互換なキー追加や列挙値追加はMINORを上げる
- キー削除、キー名変更、型変更、意味変更、既存状態の不変条件変更はMAJORを上げる
- `completed` または `error` を実際に生成可能にし、その必須データを追加する変更は少なくともMINORを上げる

バージョン更新時は、設計書、`SCHEMA_VERSION`、`RESULT_KEYS`、シリアライズ規則、単体テスト、READMEを同じ変更単位で更新する。

新しい実装は、入力内の `schema_version` や既存結果ファイルのバージョンから自動的に出力バージョンを選ばない。1つの実装バージョンは1つの `SCHEMA_VERSION` だけを生成する。

既存結果ファイルの暗黙的な移行は行わない。将来バージョンを公開する前に、既存ファイルを保持するか、明示的に再生成するか、別名で併存させるかを移行設計で決定する。既知でない出力バージョンを読み取る後続処理は、推測で処理せず明示的に拒否する。

## 決定的なJSONシリアライズ

初期版の出力値はすべてJSON stringである。次の方法で完成済みJSONバイト列を構築する。

- 出力オブジェクトのキー順は `RESULT_KEYS` だけから決定する
- 配列順は入力順だけから決定する
- `schema_version` は `SCHEMA_VERSION` だけから設定する
- `market_id` と `analysis_reference_time` は入力文字列を変換せず使用する
- `status` は固定文字列 `pending` とする
- JSON stringのキーと値は `json.dumps(value, ensure_ascii=False)` でエスケープする
- インデントは半角スペース2文字
- コロン後は半角スペース1文字
- 改行は常にLF（`\n`）
- 文字コードはUTF-8
- BOMは付けない
- ファイル末尾にはLFを1個付ける
- OS固有のテキスト改行変換を避け、完成したUTF-8バイト列をバイナリ書き込みする

正式出力には、実行日時、処理時間、ランダム値、一時ファイル名、ホスト情報、ロケール依存値を含めない。

同じ入力ファイルの同じバイト列からは、次がすべて同じになる。

- 出力パス
- 出力要素数
- 配列順
- キー順
- 各文字列の表記とエスケープ
- インデント
- 改行
- 末尾改行
- 正式JSON全体のバイト列

## 原子的保存と既存出力保護

入力ファイルの読み込み、JSON解析、全入力要素の検証、全出力要素の生成、正式JSONバイト列の構築がすべて成功するまで、一時ファイルを作成しない。

保存は次の順で行う。

1. 出力先と同じディレクトリへ一時ファイルを作成する
2. 完成済みJSONの全UTF-8バイト列を書き込む
3. 書き込み内容を `flush()` する
4. `os.fsync()` で一時ファイルの内容を同期する
5. 一時ファイルを閉じる
6. `os.replace()` で既存の正式出力を原子的に置き換える

一時ファイルの作成、書き込み、同期、クローズ、置換のいずれかに失敗した場合は、置換前の既存結果JSONを保持する。残った一時ファイルはベストエフォートで削除し、削除失敗によって元のエラーを置き換えない。

`os.replace()` が成功した後は、新しいJSONを正式出力とする。その後の処理で正式出力を変更しない。

入力JSONは読み取り専用で開き、実行前後で内容を変更しない。

## 正常終了とエラー

### 正常終了

- 1件以上: 全要素を `pending` として保存し、出力パスと件数を標準出力へ表示して終了コード0
- 0件: 正確な `[]\n` を保存し、出力パスと `分析結果0件` を標準出力へ表示して終了コード0

### エラー

次の場合は標準エラーへ `エラー: <理由>` を表示し、終了コード1とする。

- 入力となる `analysis_input_*.json` が存在しない
- 選択された入力ファイル名が規定形式ではない
- 入力ファイルを読み込めない
- UTF-8 BOM、不正なUTF-8、空ファイル、JSON構文エラー
- トップレベルが配列ではない
- 配列要素がオブジェクトではない
- 必須12キーが不足している
- 必須キーの型が不正である
- JSON object内に重複キーがある
- 数値が非有限である
- 市場IDが空または重複している
- 分析基準日時が不正または全要素で不統一である
- 出力JSON生成に失敗した
- 一時ファイルの作成、書き込み、同期、クローズ、置換に失敗した

エラー時は既存の正式な分析結果JSONを新規作成または変更しない。

## テスト方針

実装時に外部通信を行わない単体テストを追加し、既存テストと合わせて全件実行する。

### 入力選択とファイル名

- `analysis_input_*.json` のファイル名昇順で最後を選ぶ
- ファイル更新日時が選択に影響しない
- 規定外の最新ファイル名を入力不正とし、古いファイルへフォールバックしない
- 実在しない暦日や時刻を拒否する
- 入力名から同じ日時の `analysis_result_*.json` を導出する

### 入力検証

- トップレベル配列だけを受理する
- 空配列を受理する
- 各要素がオブジェクトであることを要求する
- 必須12キーと各型を検証する
- JSON numberの整数と小数を受理し、真偽値を数値として拒否する
- `NaN`、正負の `Infinity` を拒否する
- UTF-8 BOM、不正なUTF-8、空ファイル、不正JSONを拒否する
- 重複JSONキーを拒否する
- 空または空白だけの市場IDを拒否する
- 市場ID重複を拒否する
- タイムゾーンなしまたは不正な分析基準日時を拒否する
- 全要素の分析基準日時が文字列として完全一致することを要求する
- 未知キーを許容し、出力へ含めない
- 入力の `schema_version` の値と型にかかわらず出力へ継承しない

### 出力契約とバージョン

- 入力順を維持する
- 入力件数と出力件数が一致する
- 各位置で市場IDと分析基準日時が対応する
- `RESULT_KEYS` の順序で4キーを出力する
- 全要素の状態が `pending` である
- 全要素の `schema_version` が `SCHEMA_VERSION == "1.0"` と一致する
- 複数市場でも異なるバージョンが混在しない
- 入力の `schema_version` で出力バージョンを上書きできない
- 日本語、引用符、バックスラッシュ、制御文字を正しくエスケープする
- UTF-8 BOMなし、LF改行、2スペースインデント、末尾LFを確認する
- 入力0件で出力が正確に `b"[]\n"`、表示が `分析結果0件`、終了コード0
- 同じ入力を2回処理した結果がバイト単位で一致する

### 既存成果物と失敗時保護

- 入力JSONが実行前後でバイト単位に不変である
- 入力不正時に既存結果JSONを新規作成または上書きしない
- 一時ファイルの書き込み失敗時に既存結果JSONを保持する
- `os.replace()` 失敗時に既存結果JSONを保持する
- 正常時だけ既存結果JSONを原子的に置き換える
- AI、Web検索、ニュース検索、確率予測、売買、認証、外部通信を行わない
- `fetch_markets.py`、`select_candidates.py`、`prepare_analysis_input.py` の既存テストが引き続き成功する
