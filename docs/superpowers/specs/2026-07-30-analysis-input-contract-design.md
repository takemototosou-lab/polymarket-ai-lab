# AI分析入力契約 設計仕様

## 目的

最新の候補CSVを、後続のAI分析が読み込む決定的なJSONへ変換する。

この段階で追加する `prepare_analysis_input.py` は、ローカルCSVからローカルJSONへの純粋な変換機に限定する。AI API、ニュース検索、確率予測、売買、認証、外部通信は行わない。

## 責務と変更範囲

実装段階では次のファイルだけを追加または更新する。

- 新規: `prepare_analysis_input.py`
- 新規: `tests/test_prepare_analysis_input.py`
- 更新: `.gitignore`
- 更新: `README.md`
- 更新: `plan.md`

既存の `fetch_markets.py`、`select_candidates.py`、市場CSV、候補CSV、`requirements.txt` は変更しない。依存ライブラリは追加せず、Python標準ライブラリだけを使う。

## 入力ファイル

### 選択規則

`data/candidates_*.csv` に一致する通常ファイルを、ファイル名の文字列昇順で並べた最後の1件を入力とする。更新日時は使わない。

選ばれたファイル名は、次の形式へ完全一致しなければならない。

```text
candidates_YYYY-MM-DD_HHMM.csv
```

日付と時刻は、実在する暦日・24時間表記として検証する。形式不正なら入力不正とする。

### 必須列

入力CSVには次の12列が必要である。列順は問わず、追加列は許可するがJSONへは出力しない。

1. `取得日時`
2. `市場ID`
3. `市場`
4. `YES価格`
5. `NO価格`
6. `出来高`
7. `流動性`
8. `締切日`
9. `URL`
10. `カテゴリ`
11. `締切までの日数`
12. `選定理由`

入力CSVはUTF-8 BOMの有無を問わず、`utf-8-sig` で厳密に読み込む。不正なUTF-8は入力不正とする。

### 行検証

データ行が1件以上ある場合は、次を検証する。

- 全行の `取得日時` が空白を含めて完全に同じ文字列である
- `取得日時` がタイムゾーン付きISO 8601日時として有効である
- `市場ID` が空文字列または空白だけではない
- 5つの数値列が後述の数値契約を満たす

`市場`、`締切日`、`URL`、`カテゴリ`、`選定理由` は、入力文字列をそのまま出力する。変換機では再分類、URL正規化、締切再計算、並び替え、重複排除を行わない。

ヘッダーだけでデータ行が0件の候補CSVは有効入力とする。取得日時を持つ行がないため、行単位の取得日時検証は行わず、空配列JSONを正常出力する。

## 出力ファイル

入力ファイル名の接頭辞と拡張子を置き換え、同じ `data` ディレクトリへ出力する。

```text
入力: data/candidates_2026-07-30_2204.csv
出力: data/analysis_input_2026-07-30_2204.json
```

出力名は入力ファイル名からだけ導出する。データ行の取得日時とは照合しない。この規則により、候補0件でも実行日時に依存せず出力名を確定できる。

同じ入力ファイルに対する再実行では、同じ出力パスを原子的に置き換える。

## JSON構造

トップレベルは市場オブジェクトの配列とする。ラッパーオブジェクトやメタデータは追加しない。

配列内の市場順序は入力CSVの行順をそのまま維持する。

### キー順

市場オブジェクトのキー順は、`prepare_analysis_input.py` の単一定数 `JSON_KEYS` で次の順に一元管理する。

1. `市場ID`
2. `市場`
3. `YES価格`
4. `NO価格`
5. `出来高`
6. `流動性`
7. `締切日`
8. `カテゴリ`
9. `締切までの日数`
10. `URL`
11. `分析基準日時`
12. `選定理由`

`分析基準日時` の値には、同じ行の `取得日時` の入力文字列を一切変換せず使用する。

### 値の型

次の5項目をJSON numberとして出力する。

- `YES価格`
- `NO価格`
- `出来高`
- `流動性`
- `締切までの日数`

それ以外の7項目はJSON stringとして出力する。

## 数値契約

### 解析

CSVの数値文字列はPythonの `Decimal(raw_value)` で解析する。解析でき、かつ有限である値だけを受け入れる。

次は入力不正とする。

- 空文字列
- 数値として解析できない文字列
- `NaN`
- `sNaN`
- `Infinity`
- `-Infinity`

`Decimal` が有限数として受理する次の表記は許可する。

- 先頭の正符号: `+1.20`
- 先頭ゼロ: `01.20`
- 指数表記: `1E+3`, `1e-3`
- 前後の空白や桁区切りのアンダースコアなど、実装時に使用するPythonバージョンの `Decimal` が有限数として受理するその他の表記

入力構文の許可範囲は `Decimal(raw_value)` の仕様を正本とする。JSON出力では入力表記を保持せず、次の固定規則で正規化する。

### 正規化

数値は丸めず、次の順でJSON numberの文字列へ変換する。

1. 数学的にゼロなら、符号と小数点以下桁数に関係なく `0`
2. ゼロ以外は10進固定小数点表記へ変換し、指数表記を使わない
3. 小数点以下の末尾ゼロをすべて除去する
4. 小数部が空になった場合は小数点も除去する
5. 先頭の `+` と不要な先頭ゼロを除去する
6. ゼロ以外の負数は先頭の `-` を保持する

具体例:

| CSV入力 | JSON出力 |
| --- | --- |
| `0.10` | `0.1` |
| `+01.20` | `1.2` |
| `42.00` | `42` |
| `-0.00` | `0` |
| `1E+3` | `1000` |
| `1e-3` | `0.001` |
| `-001.2300` | `-1.23` |

標準JSONシリアライザへ `float` を渡す方式は使わない。これにより2進浮動小数点への変換と丸めを避ける。

## 決定的なJSONシリアライズ

市場オブジェクトは平坦な固定構造であるため、次の方法でJSONテキストを構築する。

- JSON stringのキーと値は `json.dumps(value, ensure_ascii=False)` でエスケープする
- JSON numberは前節の正規化済み文字列を引用符なしで配置する
- インデントは半角スペース2文字
- 改行は常にLF（`\n`）
- 文字コードはUTF-8
- BOMは付けない
- ファイル末尾にはLFを1個付ける
- 配列、オブジェクト、カンマ、コロンの配置を固定する
- OS固有のテキスト改行変換を避けるため、完成したUTF-8バイト列をバイナリ書き込みする

`ensure_ascii=False` により、日本語を `\uXXXX` へ置き換えずUTF-8で直接記録する。制御文字、引用符、バックスラッシュなどJSON上エスケープが必要な文字は `json.dumps` の規則でエスケープする。

候補0件の出力は、次の3バイトとする。

```text
[]\n
```

16進表記:

```text
5B 5D 0A
```

## 原子的な保存

既存JSONを壊さないため、出力は次の順で保存する。

1. 出力先ディレクトリと同じディレクトリへ一時ファイルを作る
2. 完成済みJSONの全UTF-8バイト列を一時ファイルへ書く
3. `flush()` を実行する
4. `os.fsync()` で一時ファイルの内容を同期する
5. 一時ファイルを閉じる
6. `os.replace()` で既存出力を原子的に置き換える

入力検証とJSONバイト列生成がすべて成功するまで、一時ファイルを作成しない。

書き込み、同期、クローズ、置換のいずれかに失敗した場合は終了コード1とし、置換前の既存JSONを保持する。残った一時ファイルはベストエフォートで削除する。一時ファイルの削除失敗は、元のエラーを置き換えない。

`os.replace()` が成功した後は新しいJSONが正式な出力であり、その後の処理は出力内容を変更しない。

## 正常終了とエラー

### 正常終了

- 1件以上: JSONを保存し、出力パスと `分析入力N件` を標準出力へ表示して終了コード0
- 0件: `[]\n` を保存し、出力パスと `分析入力0件` を標準出力へ表示して終了コード0

### エラー

次の場合は標準エラーへ `エラー: <理由>` を表示し、終了コード1とする。

- 入力候補CSVがない
- 選択された入力ファイル名が規定形式ではない
- 入力CSVを読み込めない
- 必須列が不足している
- 取得日時が不正または不統一
- 市場IDが空
- 数値が不正または非有限
- JSON生成に失敗した
- 一時ファイルの作成、書き込み、同期、クローズ、置換に失敗した

エラー時は既存の正式JSONを新規作成または変更しない。

## 決定性

同じ入力ファイルの同じバイト列に対して、次を保証する。

- 同じ出力パス
- 同じ配列順
- 同じキー順
- 同じ文字列エスケープ
- 同じ数値表記
- 同じインデント
- 同じ改行
- 同じ末尾改行
- バイト単位で同じJSON

実行日時、ロケール、OSの改行規則、ファイル更新日時、ランダムな一時ファイル名は正式JSONの内容に影響しない。

## テスト方針

外部APIへ接続しない単体テストを追加し、既存テストと合わせて全件実行する。

- `candidates_*.csv` のファイル名昇順で最後を選ぶ
- 規定外の最新ファイル名を入力不正とする
- 必須12列を検証し、追加列は無視する
- 行順を維持する
- 全行の取得日時完全一致を要求する
- `分析基準日時` が入力文字列と完全一致する
- `JSON_KEYS` の順序どおり出力する
- 日本語、引用符、バックスラッシュ、制御文字を正しくエスケープする
- UTF-8 BOMなし、LF改行、2スペースインデント、末尾LFを確認する
- `0.10`, `+01.20`, `42.00`, `-0.00`, `1E+3`, `1e-3`, `-001.2300` の固定数値表現を確認する
- 空文字列、非数値、`NaN`、`sNaN`、正負の `Infinity` を拒否する
- 候補0件で出力が正確に `b"[]\n"`、表示が `分析入力0件`、終了コード0
- 同じ入力を2回変換したJSONがバイト単位で一致する
- 入力CSVが実行前後でバイト単位に不変である
- 入力不正時に既存JSONを作成または上書きしない
- 一時ファイルの書き込み失敗時に既存JSONを保持する
- `os.replace()` 失敗時に既存JSONを保持する
- 正常時に既存JSONを置き換える
- `fetch_markets.py` と `select_candidates.py` の既存テストが引き続き成功する
