# 分析特徴量の参考設計メモ

利用者との比較整理から採用候補の評価指標だけを記録する。外部Botのコード、設定、credential、売買ロジックは導入しない。リポジトリの現行機能を検証済みとする資料でも、収益性の証明でもない。実装・追加通信・課金の承認を意味しない。

## 順序

1. Phase 2Aの完全オフライン基盤を完成・レビュー
2. resolution-aware照合
3. external_probability_gap
4. complete_set_net_gap
5. 板スナップショットの時系列化
6. 急変検出
7. replicability_score

## 採用候補

| 指標 | 記録する関係 | 採用前の確認 |
| --- | --- | --- |
| external_probability_gap | 対応する外部確率 − Polymarket YES価格 | 解決条件、対象、締切・判定時点、確率の向き、価格時点が一致すること。不一致は比較不能 |
| complete_set_net_gap | 1セットの条件付き償還額 − YES/NO両側を実際に取得する総費用 | 同一市場の排他的・網羅的outcome。best askだけでなく数量別板深度、手数料、slippage、時点差、約定可能性。VWAPへ含めたslippageを重複計上しない |
| replicability_score | 他者の観測損益を自己条件で再現できる程度 | 観測遅延、流動性、約定可能性、資金量、費用、未実現損益・生存者バイアス。式・重み・値域は未決定 |

いずれも**売買シグナルではなく分析特徴量**。正のgapだけで利益、裁定成立、優位性を認定しない。価格・情報源・解決条件のas-ofを保存し、後知恵による照合を避ける。現行の候補条件、カテゴリ判定、候補順、schemaには追加しない。

## 導入ゲート

必要な入力・欠損処理・照合拒否条件・数値表現・検証用過去データを別設計で固定する。外部データのライセンス、保存条件、API費用・上限は導入時に確認する。APIキーの存在だけでは実通信せず、別途明示承認と予算を必要とする。wallet接続・注文・copy trading・自動執行は対象外。
